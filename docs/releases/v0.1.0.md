# cad-render v0.1.0 — first public release

Headless B-rep CAD as an HTTP service for agents and scripts: build123d scripts in, STL / STEP /
3MF / PNG out, plus mesh convert/repair and Zoo text-to-CAD — one Docker container, file in / file out.

## Highlights

- **`POST /render`** runs a build123d script (project tarball, single file or inline source) with
  `-D name=value` defines and exports STL, STEP, 3MF or a PNG preview. Exact fillets, chamfers and
  threads on OpenCascade B-rep; STEP in and out.
- **`POST /convert`** and **`POST /repair`**: STEP ↔ mesh conversion (STL/3MF/OBJ/PLY/PNG) and a
  repair pass (merge, de-duplicate, re-orient, fill holes, manifold3d) that reports watertightness.
- **`POST /zoo`**: text prompt → KCL via Zoo's copilot → STEP/STL/3MF/OBJ/PLY/GLB (optional, needs
  `ZOO_API_TOKEN`).
- **Agent-friendly contract**: `X-Cad-Volume-mm3`, `X-Cad-Bbox`, `X-Cad-Warnings`, `X-Cad-Seconds`,
  `X-Cad-Empty` headers or JSON with the worker log (`log=1`); empty geometry is exit 3 in the CLI,
  which turns a fit check into one command.
- **`bin/cad-render` CLI** with `render`/`convert`/`repair`/`zoo`, exit codes 0/1/2/3/4/5, and
  `--to-bb` to upload the result to a Bambuddy library and run a slicer pipeline by name.
- **Hardened by default**: read-only rootfs, tmpfs `/tmp`, `cap_drop: ALL`, `no-new-privileges`,
  non-root user, memory limit, bounded job queue, per-job hard timeout with process-group kill.
- **`bin/verify`** smoke contract with an analytic-volume check on the bundled `examples/bracket.py`.

## Quick start

```sh
git clone https://github.com/rojosinalma/cad-render.git
cd cad-render
cp .env.example .env            # ZOO_API_TOKEN only if you want /zoo
docker compose up -d            # pulls ghcr.io/rojosinalma/cad-render:0.1.0
curl http://localhost:9292/health
bin/cad-render examples/bracket.py -o bracket.stl
```

Everything is configured through environment variables with generic defaults — see
[docs/configuration.md](../configuration.md).

## Known limitations

- **Zoo path is websocket + CLI, not REST.** Zoo removed the `POST /ai/text-to-cad/{format}` REST
  endpoint upstream, so `/zoo` talks to the copilot websocket (which returns KCL) and exports through
  the pinned `zoo` CLI. A whole run takes roughly 35–60 s and depends on Zoo's service.
- **PNG is a software isometric render** (matplotlib, tessellated mesh): fine for a quick look, not a
  photoreal or interactive viewer.
- **No authentication.** Scripts are arbitrary Python executed in the container. Run it on a trusted
  network for trusted clients, or behind an authenticating reverse proxy.
- **x86_64 only.** The `zoo` CLI binary pinned in the Dockerfile is the `x86_64-unknown-linux-musl`
  build; arm64 hosts need a different binary (or to drop `/zoo`).
- Mesh → STEP conversion is refused by design (STEP needs B-rep geometry).
